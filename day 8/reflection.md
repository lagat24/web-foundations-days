# Day 8 Reflection

The most difficult concept in the course was designing a system that remains correct when many users make requests at the same time. 
It was easy to describe an API or create database tables, but harder to understand what happens when two customers try to reserve the same seat. 
I overcame this by breaking the process into steps and applying database transactions, row locks, and unique constraints. 
This helped me understand why the database must be the final authority on seat availability.

Based on feedback from my capstone, I would improve the implementation and testing of features that I currently understand more conceptually than practically. 
I would make the code easier to maintain, test error cases more thoroughly, and improve the user experience when something goes wrong. 
I would also explain my technical decisions more clearly instead of focusing only on getting the application to work.

Next, I want to learn more about backend development, especially database transactions, API security, automated testing, and reliable deployment. 
I also want to practise implementing features and debugging them independently rather than relying too heavily on AI-generated solutions. 
That will help me turn my understanding of system structure into stronger practical skills.
